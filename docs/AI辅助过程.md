# AI 辅助过程与完成标准

模型及设置由作者确认：GPT-6.2 Astra（高）用于规划，GPT-6.2 Sol（高）用于执行，GPT-6.1 Sol（高）用于复核。AI 辅助的载体为 OpenAI Codex，输入为任务书、课程资料、数据文件位置及核查问题。

| 环节 | 研究判断与交付 | AI 的辅助 |
|---|---|---|
| 拆解任务 | 将要求落实为房价模型与异质性、轨迹质量与处理、进一步分析；先考虑过程规范和证据是否完整 | Astra 帮助形成检查清单、实施顺序及拟用指标 |
| 核查输入 | 统一米制距离、确认空间叠合；缺日期、编码、价格单位的部分保留假设 | Sol 生成读取、字段审计、跨源位置检查与源行号回查代码 |
| 建模与处理 | 房价有常数／线性基准及空间留出；轨迹在断点内重建，再识别停留、候选 OD 和格网分布 | Sol 执行 Python 实验、生成 CSV 和地图；代码、参数及输出留档 |
| 复核与解释 | 比较划分方向、样本量、参数和格网；以可重算证据判断稳定性，不把模型归因直接解释为因果 | Sol 6.1 按任务逐项复核，补跑排除疑点与并列格对照，核查引用并修改报告 |
| 交付 | PDF／Word 按课程篇幅排版；线上仓库提供代码、日志与汇总结果 | AI 协助编辑、整理和格式检查，作者决定取舍并在提交前验收 |

完成标准为：任务要求均有对应产物，关键数字与脚本输出一致，地图和统计分母一致，结论注明样本与假设，引用真实可追溯，最终 PDF 页数符合要求。原始日期和状态语义缺失仍是未解决的问题，不因 AI 检查通过而消失。

AI 辅助核验不等同于作者已人工逐条检查全部记录。当前公开材料支持复核分析过程；获得原始数据后可重跑详细结果。原始数据获取、事实判断和最终提交责任由作者承担。
